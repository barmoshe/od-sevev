# 0001. v2 moves to Godot 4.7 for iOS, Android and a Vercel web build

- Date: 2026-09-28
- Status: Accepted

## Context

v1.1 is Phaser 4 + Vite + TypeScript and runs only in a browser. Bar asked to improve the game
"in every aspect" and, while planning, to **switch to Godot and ship it as an iOS and Android
game**, with the web build staying on Vercel only (no itch.io, Newgrounds or CrazyGames).

The planning session (`bar_builds/lab/personal/monkey-bananas/research.md`) found:
- **In the browser, iOS clears localStorage** after 7 days without a visit, and haptics don't
  work. Both are serious for an idle game you come back to.
- **Critical v1 bugs** in saves (unreadable saves overwritten, positional producer counts) and
  hardcoded content that blocks the planned depth (milestones, achievements, a Thumbs shop).
- **Proven path:** the wandcraft sibling is already a Godot 4.7.2 mobile game, with the full
  toolchain: headless tests, web, Android, iOS Simulator and TestFlight scripts, and measured
  answers to Godot web-audio problems (its ADR 0009).

## Decision

- **Engine:** rebuild in **Godot 4.7.2, typed GDScript, Mobile renderer**, in `game/`, with
  tools copied from wandcraft into `tools/`. Portrait 720×1280 base with stretch aspect
  `expand`, so tall phones grow the stage instead of letterboxing it.
- **Specs stay canonical:** the engine-agnostic specs (`design/`, `ux/`, `motion/`, `audio/`,
  `art/`) remain the source of truth. `tools/sync_data.sh` copies the JSON into `game/data/`,
  and a test fails if the copies drift.
- **Pure simulation layer:** the rules live in `game/scripts/sim/`, which never touches
  nodes and is tested headless. The pacing bench (`PacingSim`) drives the real economy, which
  retires the duplicated JS sim.
- **Procedural identity kept:** sprites come from the same palette grids, baked at boot. Audio
  is generated from code by an offline generator, not by runtime WebAudio.
- **Branching:** work happens on branch `godot-v2`. `main` keeps serving v1.1 until parity.
  Tag `v1.1-phaser` keeps the Phaser build.

Rules changed in the port, each decided while executing and recorded here:
- **Saves v2:** producer counts are keyed by id. A v1 save (web localStorage, same origin)
  migrates by tier position. An unreadable or newer save is copied to a `.bak` file before
  anything can overwrite it. Writes are atomic. Saves export and import as an `MB2:` code.
- **Away time:** one continuous rule. The first `minAwaySec` pays full rate and the rest pays
  `offline.efficiency`, capped at `offline.capSec`. v1 paid 100% at 59 s and 50% at 61 s.
- **Thumbs:** they will be spendable in the Thumbs shop (phase 6) the way Cookie Clicker spends
  heavenly chips. `thumbs_owned` (lifetime) still drives the multiplier, and spending only
  raises `thumbs_spent`, so spending never lowers income. This supersedes the plan's "while
  held" wording, which would have made spending a trap.

## Consequences

- One codebase ships to both stores and the web. iOS builds need Bar's Mac with Xcode. Store
  accounts ($99/yr Apple, $25 Google) are Bar's call, needed only at the store-readiness phase.
- The v1.1 Vercel project is git-connected. At parity, git deploys get turned off and the
  Godot web build ships through `tools/deploy_web.sh` to the same URL. Until then, test
  deploys go to a separate project (`MB_VERCEL_PROJECT`, default `monkey-bananas-v2`).
- The bundle is no longer a 464 KB JS file but a Godot wasm build of a few MB, which is
  acceptable for a game you install or add to the home screen.
